Webhook signature verification and HTTP 401 recovery

Version 3.2. Support visibility: internal. Error codes: WS-WEBHOOK-401 and WS-SIG-MISMATCH.

Symptom

Delivery logs show HTTP 401, or the consumer rejects the request with signature mismatch after a signing secret rotation.

Diagnostic order

  1. Confirm the consumer verifies the X-Northstar-Signature header using HMAC-SHA256 over the raw request body.
  2. Check whether the workspace is in dual-secret mode. During rotation, both current and next secrets must be accepted for at least 24 hours.
  3. Compare the timestamp skew. Reject deliveries older than five minutes to prevent replay, but allow clock skew up to 60 seconds.
  4. Replay one failed delivery with the same event identifier. Consumers must remain idempotent on event identifier.
  5. Only after the consumer accepts both secrets, retire the old secret. Bulk secret force-reset requires a support lead.

Safety boundary

Support agents must not paste signing secrets into chat, tickets that customers can read, or Phoenix traces. Secret rotation is a privileged change and requires HITL when performed by OmniSupport tools.

Success criteria

One replayed delivery returns HTTP 2xx, signature verification succeeds with the active secret, and no duplicate business side effect is created for the same event identifier.
